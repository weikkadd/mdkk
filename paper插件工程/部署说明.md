# PanelDeploy 插件部署说明

> 修复版插件：去除了原版的"伪装 EssentialsX / jar 覆盖"逻辑，其余部署能力保留。
> **仅用于你自己拥有或被授权管理的服务器。**

## 工程结构

```
paper插件工程/
├── pom.xml                                 Maven 构建配置（paper-api 1.20.4，Java 17）
├── src/main/java/com/paneldeploy/PanelDeploy.java   插件源码（修复版）
├── src/main/resources/plugin.yml           插件描述文件
├── env-配置示例.txt                         .env 配置参考
├── target/PanelDeploy-1.0.0.jar            ★ 已编译好的插件
└── 部署说明.md                              本文件
```

## 相比原版的改动

| # | 改动 | 原因 |
|---|------|------|
| 1 | 删除 `setupDisguise` / `restoreMaliciousJar`（下载真 EssentialsX jar 覆盖自己） | 只对躲避管理员有用；自己服务器上运行中插件目录躺的是真 EssentialsX，只会造成困扰 |
| 2 | 修复 `GITHUB_AUTH="用户名:"密钥` 引号错位 bug | 原写法生成的 bash 变量会把 Token 丢掉，私有仓库永远拉不到代码 |
| 3 | `REPO_URL` / `GITHUB_AUTH` 改为从 `plugins/PanelDeploy/.env` 读取 | 不用改 Java 源码重新编译，改配置文件重启即可 |
| 4 | 工作目录 `logs/.mcchajian` → `logs/.paneldeploy` | 配合去掉伪装 |
| 5 | `.env` 默认 `SYSTEM_GUARD_ENABLED=false` | 守护开启时服务器会被拒绝停止并强制重启；自己的服务器默认关 |
| 6 | 数据持久化路径与当前 index.js 对齐 | 原脚本拷贝的是旧版路径（`node_modules/.bots_config.json` 等），机器人/哪吒/酒馆配置每次重新部署都会丢；现改为 `bots_config.json`、`.Error log/.node_module_cache`、`.tavern/config.json`、`.music_cache` |
| 7 | `URI.toURL()`（需 Java 20+）→ `new URL()` | 使插件可在 Java 17 环境编译和运行 |
| 8 | 新增 `plugin.yml` 和 `pom.xml` | 原始 txt 只有 Java 源码，没有这两个文件无法编译运行 |

## 部署步骤

### 第 1 步：准备 GitHub 仓库

1. 新建 GitHub 仓库（**建议公开**，私有仓库需要额外配 Token）
2. 把 `index.js` 和 `package.json` 放到仓库**根目录**（分支名 main 或 master 都可以）

### 第 2 步：安装插件

1. 把 `target/PanelDeploy-1.0.0.jar` 放进 MC 服务端的 `plugins/` 文件夹
2. 启动服务端，插件会自动生成 `plugins/PanelDeploy/.env`
3. 停止服务端，编辑 `.env`：

```ini
REPO_URL=https://github.com/你的用户名/你的仓库
GITHUB_AUTH=
SYSTEM_GUARD_ENABLED=false
```

- 私有仓库：`GITHUB_AUTH=你的用户名:ghp_xxxxxxxx`（Token 用 classic 类型，勾选 repo 读权限）
- `SYSTEM_GUARD_ENABLED=true` 时：服务器被停止会自动重启，且 watchdog 每 15 秒检查 25565 端口、掉线自动拉起服务端（需要重启服务器想彻底退出时改成 false）

### 第 3 步：启动并获取面板地址

1. 启动服务端，插件自动执行：下载 Node 22 → 下载 cloudflared → 拉取你的仓库 → npm install → pm2 启动面板 → 建立 trycloudflare 免费隧道
2. 控制台出现这一行即为成功：

```
[HH:mm:ss INFO]: [Connection] Binding remote endpoint to: https://xxxx-xxxx-xxxx.trycloudflare.com
```

3. 浏览器打开该地址 → 伪装的 easydss 404 页面 → **点击版本号 `easydss/1.13.0` 中间的点** → 输入密码 `666` 进入面板

## 注意事项

- **trycloudflare 免费隧道每次重启地址都会变**，需要固定域名要在面板"音乐加速"里填 `ARGO_DOMAIN` + `ARGO_AUTH`（Cloudflare Zero Trust 的 Tunnel Token）
- 面板密码 `666` 写死在 `index.js:2872`（`if(inp.value==='666')`），建议改掉
- 面板所有 `/api/*` 接口无鉴权、密码仅前端校验，**不要把隧道地址泄露给别人**
- 环境要求：服务端 Java 17+（Paper 1.18+），服务器可出站访问 nodejs.org / github.com
- 面板配置重启不丢：机器人配置、哪吒探针、酒馆任务、音乐节点缓存会在每次重新部署时自动保留（见改动 #6）
- 服务器上每次重新部署会 `pkill -f cloudflared`，如果你在同一台机器上跑着别的 cloudflared 隧道会被误杀

## 自己重新编译

改了 Java 源码后：安装 JDK 17+ 和 Maven，在 `paper插件工程/` 下执行 `mvn package`，产物在 `target/PanelDeploy-1.0.0.jar`。
